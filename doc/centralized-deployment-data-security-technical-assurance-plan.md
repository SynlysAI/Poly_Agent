# 集中部署模式数据安全技术保障方案

## 1. 文档信息

| 字段 | 内容 |
|---|---|
| 文档状态 | Draft |
| 日期 | 2026-07-31 |
| 适用范围 | 平台统一集中部署、不提供私有化交付的模式 |
| 目标 | 保障客户研发数据在集中部署场景下的传输、存储、访问、计算和交付安全 |

## 2. 方案目标

本方案围绕客户研发数据安全，采用三层技术体系：

1. 全链路基础安全防护。
2. 企业外部用户精细化权限管理。
3. 可选轻量联邦推理方案。

方案只针对集中部署模式的数据安全保障，不扩展到私有化交付或其他平台能力建设。

## 3. 总体原则

1. 默认集中部署，所有数据流转都在统一平台内受控完成。
2. 安全控制优先于便利性，所有外部访问均遵循最小权限原则。
3. 关键动作必须可追溯，审计留痕是默认要求。
4. 高敏数据默认不出域，联邦推理只作为可选方案。
5. 安全能力按租户、项目和账号三个维度同时生效，避免单点控制失效。

## 4. 全链路基础安全防护

### 4.1 数据传输加密

- 客户端到平台的所有数据传输统一使用 TLS 1.3。
- 计算提交、结果查询、文件上传下载、任务状态回传等接口均纳入加密通道。
- 禁止明文传输业务数据、凭证和结果文件。

### 4.2 数据存储加密

- 平台侧业务数据统一采用 AES-256 存储加密。
- 存储范围覆盖原始数据、计算结果、临时中间文件和业务附件。
- 业务系统不保存明文敏感数据副本。

### 4.3 临时数据清理

- 计算任务结束后，自动清理服务端临时缓存与中间文件。
- 清理对象包括运行时缓存、临时解压目录、中间产物和一次性派生文件。
- 清理逻辑应覆盖正常结束、失败结束和中断结束三种状态。

### 4.4 客户自主删除

- 支持客户自主删除全量业务数据。
- 删除动作应覆盖与该客户相关的业务数据、任务结果和可恢复副本。
- 删除后应确保后续查询与调取不再返回已删除内容。

### 4.5 强租户逻辑隔离

- 多租户的数据、计算任务、存储路径保持完全逻辑隔离。
- 租户标识必须贯穿数据模型、任务调度、结果查询和文件访问全过程。
- 系统架构层面禁止跨租户访问与调取。
- 任何跨租户关联查询都应直接拦截，而不是事后过滤。

## 5. 企业外部用户精细化权限管理

### 5.1 权限模型

- 采用基于角色的权限分配机制（RBAC）。
- 权限粒度覆盖数据访问、算法调用、结果查看等核心操作。
- 支持按岗位、项目配置不同权限组合。
- 所有授权默认遵循最小权限原则。

### 5.2 账号认证

- 支持多因子身份认证。
- 支持访问 IP 白名单限制。
- 外部访问账号必须经过身份校验后才能进入业务系统。

### 5.3 操作留痕

- 所有外部用户操作全程留痕。
- 留痕内容至少覆盖账号、时间、IP、操作类型、目标资源和结果状态。
- 日志应支持按账号、项目和时间范围追溯。

### 5.4 项目级隔离

- 支持同一企业内项目级数据隔离。
- 项目负责人可自主管理本项目成员权限。
- 默认禁止跨项目查看、调用和流转数据。
- 项目成员权限变更应立即生效，并同步进入审计记录。

## 6. 轻量联邦推理方案（高敏数据可选）

### 6.1 适用场景

- 适用于核心研发数据不愿出域的客户。
- 适用于希望保留数据在企业内网、但又需要使用标准化算法能力的场景。

### 6.2 交付形态

- 将标准化算法模型封装为容器化离线推理包。
- 推理包下发至客户本地环境运行。
- 客户本地只接收模型包、运行依赖和标准输入输出接口，不接收原始数据出域链路。

### 6.3 数据流转方式

- 客户原始数据全程留存企业内网。
- 平台与客户本地环境只交互最终计算结果。
- 不要求平台获取客户原始训练数据或中间敏感明细。

### 6.4 落地约束

- 无需特殊硬件支持。
- 通过标准容器化方式交付，降低部署改造成本。
- 以短周期落地为目标，优先保证可用性和安全边界清晰。

## 7. 实施拆分建议

### 7.1 第一阶段：基础安全防护

- 完成 TLS 1.3 和 AES-256 的统一落地说明。
- 明确临时缓存和中间文件清理策略。
- 明确租户隔离边界和数据删除范围。

验收重点：
- 传输、存储、临时文件和删除链路均有明确控制点。
- 不存在跨租户访问路径。

### 7.2 第二阶段：外部用户权限治理

- 落地 RBAC 权限模型。
- 补齐 MFA、IP 白名单和审计留痕要求。
- 完成项目负责人对成员权限的自主管理逻辑。

验收重点：
- 不同角色仅能访问授权范围内的数据和操作。
- 所有关键操作可追溯。

### 7.3 第三阶段：可选联邦推理交付

- 将标准化算法模型整理为离线容器包。
- 明确本地运行、结果回传和版本管理边界。
- 给出高敏客户的可选交付路径。

验收重点：
- 原始数据不出域。
- 平台只接收最终结果。
- 交付包不依赖特殊硬件。

## 8. 边界说明

1. 本方案不包含私有化交付改造。
2. 本方案不扩展设备链路或平台其他业务功能。
3. 本方案只围绕集中部署模式的数据安全、权限控制和可选推理交付展开。
